comparing traces with `st2fb.compare`. The forward path and FORTE are not involved. Do not edit by hand, except through `corpus_hard/mutation_survivor_notes.json`.

## Notes on what the mutants exercise

- **`r03_sequence_aoi`, the RES on abort and the RES at the end of a cycle.** All the statements that write out these two RES calls can be removed with no visible change. Each sets `StepNo` to 0 on the same scan, so the `TONR` call later in that scan is disabled, and that alone clears `ACC` and `DN` and overwrites `EN`, `TT` and `PREV`. So they exercise nothing: a migration may leave them out and be correct. The two RES calls between steps do matter, for `ACC`, `DN` and `PREV`, and removing any of those is killed.
- **`r02_fill_retry_aoi`, `Retries_PREV`.** The counter's edge memory cannot show, since its input, the open timer's `DN`, is high for one scan at a time. And the dialect file's rule that RES on a counter keeps the previous input cannot show either, since `RES(OpenTimer)` clears that input on the same scan. `scripts/check_plausible_faults.py` confirms the second. So CTUD's edge detection is read here but not tested by this program. No other program uses CTUD.
- **The `EN` and `TT` members of Logix timers** are written and never read in `r01`, `r02` and `r03`, except where a program copies them to an output. The dialect file gives them meaning, but only `r01`'s `DelayEnabled` and `Starting`, `r02`'s `WaitingRetry` and `r04`'s `Timing` observe one.
- **Out-of-range index mutants** are marked `meaningless`. They read or write outside an array, which is undefined in C, and the fact that they survive says nothing about the stimulus.
